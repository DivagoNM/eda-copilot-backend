# Калибровка весов FastRoute — 2026-10-07

## Границы эксперимента

Запрос: менять только веса, сохранить недорогие пересечения с обычными
сетями, сильнее защищать явно заданные `signalPath` и `criticalPair`.
Формулы, генерация кандидатов, Beam, локальные улучшения, физические
ограничения, фильтры сетей, DSL и worker/backend settings не меняются.
Все полные прогоны выполнены последовательно через
`npm run debug:pcb-layout -- capture <fixture>`.

Исходный STM32 DSL содержит пользовательские незакоммиченные изменения;
они сохранены. Для сравнения сняты свежие baseline captures, а не взяты
старые результаты другого DSL. Хеши входов и native addon записаны в
`run-manifest.json` каждого capture. Локальные подробности эксперимента:
`debugging/route-weight-calibration-2026-10-07/`.

## Наборы весов

В таблице показана сумма двух направленных штрафов для пересечения двух
прямых связей. FastRoute минимизирует стоимость семи вариантов пути:
если есть более дешёвый обход, реальная прибавка будет меньше табличной.
Это не безусловная цена пересечения нарисованных прямых и не запрет DRC.

| Пересекающиеся классы | Baseline | A | C | D |
|---|---:|---:|---:|---:|
| ordinary / ordinary | 6 | 6 | 6 | 6 |
| ordinary / criticalPair | 12 | 12 | 12 | 12 |
| ordinary / signalPath | 18 | 18 | 18 | 18 |
| criticalPair / criticalPair | 18 | 60 | 60 | 180 |
| criticalPair / signalPath | 24 | 120 | 120 | 300 |
| signalPath / signalPath | 30 | 180 | 180 | 450 |
| Коэффициент кубического превышения мягкого pair/path | 1 | 1 | 0.25 | 0.25 |

Последняя строка — коэффициент уже существующего члена
`W * inverseTauSquared * excess³`. Линейный член `W*d`, границы min/max,
авторские множители и веса приоритетов сохранены. Для условий с `core:true`
коэффициент остаётся 1; множитель excess для `core && hard` остаётся 100.
Обычные near/very_near и pad/topology/compactness/clearance weights не менялись.

Раньше сумма номеров классов давала одинаковый коэффициент для
ordinary/signalPath и criticalPair/criticalPair. При калибровке этим двум
ячейкам назначены отдельные веса. Таблица остаётся в единственном
`relation_score.rs`, используемом общим планировщиком CPU/GPU.

## Что измерялось

- Полное время capture, `placementOk`, сохранность инвентаря и фиксированных поз.
- Длина обычного MST и длина уникальных явно заданных pad-to-pad связей.
- Строгие пересечения прямых явно заданных связей разных сетей на совместимых
  слоях, после дедупликации; signalPath имеет приоритет над criticalPair
  для одной и той же пары точек. Это диагностическая геометрия, не второй scorer.
- Стадии до и после PostPlace, чтобы отличать улучшение поиска от исправления
  одного фиксированного кандидата. Абсолютные scores разных весов не сравниваются.

Обычные геометрические метрики переиспользуют
`scripts/experiment-placement-metrics.mjs`, явные связи — существующий
`encodeNativePostPlaceScoreProblem`. Все сравнения acceptance scores выполняет
native `refinePostPlacement` с `iterations:0`.
Пересечения важных связей перепроверены F32-предикатом `crosses` из production
`fast_route/arithmetic.rs`: локальный Rust CLI подключает этот исходник через
`#[path]`, не копируя формулу. Числа совпали с первоначальным диагностическим
подсчётом. Длины в таблицах — измерения геометрии, не компоненты нового scorer.

## Точечная проверка D4/D5

На геометрии свежего baseline STM32 после Legalize сравнивались четыре
комбинации поворотов D4/D5. Для каждого набора весов вход заново кодировался
существующим `encodeNativePostPlaceRefineProblem`; это важно, поскольку
старый native JSON уже содержит старые `inverseTauSquared`.

| Набор | Прибавка от D4: 0→180, D5=0 | Прибавка от D5: 0→180, D4=0 |
|---|---:|---:|
| Baseline | -789.08 | -703.80 |
| A | -579.92 | -668.97 |
| C | +419.09 | +29.75 |
| D | +554.09 | +2.75 |

Положительная прибавка означает, что плохой переворот больше не выгоден.
Отдельный sweep коэффициента excess на старом сохранённом native входе
подтвердил смену предпочтения D4: 1 → -789.08; 0.5 → -123.08;
0.25 → +209.92; 0.125 → +376.45. Здесь использован baseline addon,
а не новые веса пересечений. Формула считается native, не копируется в JS.

новыми запретами или критериями принятия кандидата.

У C и D **полностью совпадают финальные позы**, а не только метрики.
Поэтому D отклонён: повышенные веса не принесли пользы на проблемной плате.
Дополнительные прогоны D на контрольных платах не запускались. A не выбран,
поскольку оставляет исходные 4 пересечения важных связей.

**Оставлен C**, включая соответствующий собранный addon. В нём D4 остаётся
в 0° и PostPlace больше не добавляет два пересечения CAN_H/CAN_L.
Два оставшихся пересечения RS485_A/RS485_B уже присутствуют после Board
Package: одно signalPath/signalPath и одно criticalPair/signalPath.
Их устранение этими весами не подтверждено. Более сильный набор D их тоже
не убрал; дальнейшее повышение без нового основания не принято.

Поворот D5 в точечном тесте не является самостоятельным доказательством
качества всей RS485-компоновки. На финальной плате C он стоит в 90°.
Проверка отдельных поворотов и результат полного поиска — разные измерения.
